# What each test suite costs IN CI, for scripts/ci/run_suites.py --shard.
#
# Measured in CI, not on a laptop. The first cut of this file was local and the
# split it produced landed at 1.25 in CI against a predicted 1.00. Two reasons,
# both worth keeping:
#
#   * the R-MORE suites cost 113 s on a laptop and nothing in CI, because
#     scripts/ci/setup-r-packages.sh does not install MORE and they all skip
#     there. A laptop charges the split for work CI never does.
#   * a laptop is ~1.8x faster on the suites that do real work, but the two are
#     not related by one constant -- test_more_backend_endtoend is 1.0 s local
#     and 20.6 s in CI. Scaling a local measurement cannot substitute for
#     measuring the thing.
#
# Rows CI has published are its own numbers (run 33053631697, both shards).
# The rest are local figures scaled so the total matches what that run actually
# summed (651 s), which puts the tail at roughly the right weight without
# claiming a precision it does not have. The split needs the EXPENSIVE suites
# right and the tail is noise -- one suite is 177 s of the 651.
#
# pr.yml passes --slowest 400, so every run now publishes every suite: the next
# refresh is a straight copy of the "slowest:" table from both shards.
#
# A suite missing from this list is charged the median, so a new one is never
# assumed free. Nothing fails if the file is absent or stale -- the split falls
