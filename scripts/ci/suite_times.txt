# What each test suite costs, for scripts/ci/run_suites.py --shard.
#
# The shard used to be `position % count` over the ALPHABETICALLY sorted
# filenames, which is arbitrary with respect to cost -- and the top six suites
# are 52% of the whole budget, so which shard they land in is decided by how
# they are spelled. Measured on this file's own numbers: the parity split is
# 264 s / 198 s (ratio 1.33), a longest-processing-time split over these
# figures is 231 s / 231 s (ratio 1.00). In CI the same lottery has been worse
# -- 395 s against 81 s in run 32859901451 -- and it is what put shard 1/2 at
# 601 s against a 600 s cap in run 33010348812.
#
# Adding or renaming ONE file re-deals every suite under parity. It does not
# under a cost-aware split, which is the point: the gate's runtime should not
# depend on filename spelling.
#

# Apple-silicon laptop, 4 at a time, 248 suites, 462 s summed; CI's absolute
# numbers are roughly 1.7x these. A suite missing from this list is charged the
# median, so a new one is never assumed free. Nothing fails if the file is
# absent or stale -- the split falls back to parity.
